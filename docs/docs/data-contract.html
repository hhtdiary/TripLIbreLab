SQLite data contract

What TripLibreLab relies on inside a TripLibre travel.sqlite, and nothing more. This is the reference the importer is written against. The complete version, with every SQL statement, is docs/sqlite-data-contract.md in the repository.

i

Source of truth: TripLibre 2.1.0, database schema v6, read from TripLibre's migration and export code. Every column below is copied from those migrations. The contract has been checked against databases built from that same SQL (the fixtures) and not yet against an export from a phone; that check is marked Pending where it matters.

The file

FactValue
Name and placetravel.sqlite in hht-export-YYYYMMDD-HHMMSS/, under Files › On My iPhone › TripLibre › Exports.
How TripLibre writes itVACUUM INTO from the live database. The result is one self-contained file in rollback-journal mode: no -wal or -shm files are needed to open it, even from a read-only location.
What it containsAlways the complete database: every table, soft-deleted rows included, and all raw GPS points, whatever range or options were chosen for the export.
Schema versionPRAGMA user_version, 1 to 6 today. Migrations only add; codes are never renamed.
Other export filestrips.csv, data.json, GeoJSON and the rest are not read by TripLibreLab.

How a file is validated

In this order; the first failure stops the import with the message shown.

#CheckIf it fails
1The first 16 bytes read SQLite format 3\0."This file is not a SQLite database."
2Open read-only (mode=ro&immutable=1) and PRAGMA quick_check returns ok."The file could not be opened as a TripLibre database (damaged file)."
3Tables trips, visits and places exist with every required column listed below."This SQLite file is not a TripLibre export (expected tables are missing)."
4user_version is between 1 and 6.Version 0: unsupported. Newer than 6: a notice, then import continues if check 3 passed (recommended policy, awaiting sign-off).
5At least one row in trips with deleted = 0."This diary contains no recorded trips." An empty-diary screen, not an error.

The importer never writes to the file, never runs VACUUM or migrations, and keeps its private copy only inside the app's container.

Conventions

TopicRule
*_ts, tsUTC Unix seconds, stored as REAL.
tzIANA zone of the phone when that record was made, e.g. America/New_York. Local dates and clock times are computed in each record's own zone, so travel across zones stays right. May be NULL on old or imported rows.
CoordinatesWGS84 decimal degrees in lat, lon.
DistancesMetres, great-circle along the recorded path; straight line across a data gap.
IDsLowercase UUID strings for places, visits, trips and segments; integer autoincrement for raw points.
route_polylineGoogle encoded polyline, precision 1e-5, (lat, lon), simplified at 8 m. It carries no timestamps.
Soft deletedeleted = 1 rows are kept. Every query filters deleted = 0.
Missing valuesSQL NULL. No sentinels.
Final modeCOALESCE(mode_user, mode_auto, 'unknown').

Field map

The app's four models and the columns each one is built from. "Required" columns are those check 3 above insists on.

Place ← places

Required: id, name, lat, lon, category, merged_into. Read when present: deleted (v2+).

  • name NULL means an unnamed place. TripLibre shows its coordinates; TripLibreLab shows the category instead and never puts coordinates on a share card by default.
  • category = 'home' or 'work_school' drives the default redaction.
  • merged_into set marks a tombstone; resolve to the target.
  • Never loaded: address, notes, favorite, radius_m, source, city, region, country.

Trip ← trips (+ trip_segments)

Required: id, origin_visit_id, destination_visit_id, origin_place_id, destination_place_id, departure_ts, arrival_ts, distance_m, mode_auto, mode_user, purpose, route_polyline, has_gap, user_status, deleted, tz.

Model fieldFrom
departure, arrivaldeparture_ts, arrival_ts (both NOT NULL; arrival may be on the next local day).
originPlaceID, destinationPlaceIDThe origin / destination visit's place_id, else the trip's own *_place_id (used for manual or imported history). This is v_trips.origin_place_final.
originCoordinate, destinationCoordinateVisit centroid → place coordinate → first/last polyline vertex → nil. Nil must not crash anything.
mode, modeIsUserCorrectedCOALESCE(mode_user, mode_auto, 'unknown'); mode_user IS NOT NULL.
segmentModestrip_segments by seq, each with the same COALESCE, consecutive repeats collapsed. Shown only when more than one distinct mode.
purposetrips.purpose → destination visit purpose → default for the destination place category (table below). This is v_trips.purpose_final.
routeShapeDecoded route_polyline; shape only, empty when NULL.
hasRecordingGaphas_gap: GPS silent for more than 15 minutes during the trip; the polyline then contains a straight connector across the gap.

SELECT t.id, t.departure_ts, t.arrival_ts, t.tz,
       COALESCE(ov.place_id, t.origin_place_id)      AS origin_place_id,
       COALESCE(dv.place_id, t.destination_place_id) AS destination_place_id,
       ov.lat AS origin_lat, ov.lon AS origin_lon, dv.lat AS destination_lat, dv.lon AS destination_lon,
       COALESCE(t.mode_user, t.mode_auto, 'unknown') AS mode,
       t.purpose AS purpose_explicit, dv.purpose AS purpose_visit, dp.category AS destination_category,
       t.distance_m, t.route_polyline, t.has_gap, t.user_status
FROM trips t
LEFT JOIN visits ov ON ov.id = t.origin_visit_id
LEFT JOIN visits dv ON dv.id = t.destination_visit_id
LEFT JOIN places dp ON dp.id = COALESCE(dv.place_id, t.destination_place_id)
WHERE t.deleted = 0
ORDER BY t.departure_ts;

Stay ← visits

Required: id, place_id, arrival_ts, departure_ts, lat, lon, purpose, user_status, deleted, tz.

  • departure_ts NULL means still there when the export was made. Show "ongoing"; never invent an end.
  • lat, lon is the observed centroid of the stay, slightly different from the place's coordinate.
  • Stays for a day are those overlapping the local day, the same window query TripLibre uses:
SELECT id, place_id, arrival_ts, departure_ts, lat, lon, purpose, user_status, tz
FROM visits
WHERE arrival_ts <= :day_end_utc AND (departure_ts IS NULL OR departure_ts >= :day_start_utc) AND deleted = 0
ORDER BY arrival_ts;

TrackPoint ← raw_location_points

Optional table. Columns used: ts, lat, lon, h_accuracy, speed, course, source. There is no foreign key from raw points to trips; the only link is time, and the table can hold hundreds of thousands of rows, so it is queried only by trip window and never as a whole.

SELECT ts, lat, lon, h_accuracy, speed, course, source
FROM raw_location_points
WHERE ts >= :trip_departure_ts AND ts <= :trip_arrival_ts
ORDER BY ts;

DiaryDay ← derived

  • Date: the local calendar date of trips.departure_ts in that trip's own tz. This is TripLibre's person_day_id. A taxi ride from 23:40 to 00:15 belongs to the day it left.
  • Trips: all non-deleted trips with that date, ordered by departure, numbered from 1.
  • Stays: the overlap query above, plus the first trip's origin stay and the last trip's destination stay.
  • Listed days: V0.1 lists dates with at least one trip (TripLibre's own person-day definition also counts stay-only dates; the choice is open). A date with no rows is not evidence of no travel; recording may have been off.

Geometry fidelity

Because polylines carry no timestamps, the replay must be honest about what it animates. Every trip is drawn at exactly one of these levels, and labelled with it.

LevelData presentHow it is replayed
MeasuredTwo or more raw points inside the trip windowMarker moves point to point on the real timestamps; the stored shape is the path.
Recorded shapePolyline, but no usable raw pointsThe stored shape is drawn; the marker moves along it at uniform speed between departure and arrival. Labelled "timing interpolated".
SchematicOnly origin and destination coordinatesA dashed straight line; uniform speed. Labelled "no GPS track".
Gaphas_gap = 1The long straight connector inside the polyline (a leg of 1 km or more and at least 8 times the trip's median leg, TripLibre's own display heuristic) is drawn dashed and labelled "recording gap".
No locationNo coordinates at either endKept on the timeline, left off the map.

Edge cases the importer must survive

All of these exist in the fixtures.

  • Trip crossing local midnight; stay still ongoing (departure_ts NULL).
  • Soft-deleted trips, visits and places; a merged place tombstone.
  • A trip with neither polyline nor raw points; a trip with a polyline and has_gap = 1.
  • A trip without visits (imported or hand-made) that falls back to *_place_id, or has no location at all.
  • An unnamed place; a NULL tz; several time zones on one date.
  • A multimodal trip with segments.
  • Schema v1; a schema newer than 6; an empty database; a non-SQLite file; a SQLite file from another app.

Fields that are never read

The whole file is sensitive, but these columns are personal text or identifiers that the importer never loads into memory at all: places.address, places.notes, visits.notes, trips.notes, stamps.note, expenses.note, audit_log.old_value, audit_log.new_value, flights.booking_reference, flights.seat, and raw_location_points outside a selected trip's window. What can reach a share card is described on Replay & share.
