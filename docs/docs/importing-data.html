Using TripLibreLab

Importing a TripLibre export

TripLibreLab reads the SQLite database that TripLibre includes in every export. It opens a copy read-only, checks it, and turns it into days, trips and stops it can replay.

i

The tables, fields and checks on this page come from TripLibre's own database code and are written up in full in the SQLite data contract. The importer itself is not built yet, so the behaviour described here is the specification it will be tested against, marked Pending until it is.

Which file

Use travel.sqlite from a TripLibre export folder (hht-export-YYYYMMDD-HHMMSS/). It is a complete snapshot of TripLibre's database. TripLibreLab does not read the export's CSV, JSON or GeoJSON files.

What TripLibre's code says about this file:

  • It is written with SQLite's VACUUM INTO, so it is one self-contained file that can be opened without any companion files.
  • It is always the whole database, including raw GPS points and deleted records, whatever range you chose when exporting.
  • Timestamps ending in _ts are UTC Unix seconds; each record carries the time zone (tz) it was made in.
  • The schema version is stored in PRAGMA user_version, and TripLibre's migrations only ever add to the schema.
  • Deleted rows are kept with deleted = 1 rather than removed. TripLibreLab never shows them.

For every table and column, see TripLibre's Data dictionary.

How the file is opened Pending

  1. You choose itThrough the iOS Files picker. TripLibreLab cannot see any file you have not picked.
  2. It is copied and opened read-onlyThe copy lives only inside the app. The original export is never modified, and the copy is never written to either.
  3. It is checked before it is readIn order: is it a SQLite file; is it intact; does it have the trips, visits and places tables with the columns TripLibreLab needs; which schema version is it; does it contain any trips. The first failed check stops the import with a plain-language reason.
  4. It is normalisedRecords are converted into the app's own model: diary days, trips, stays and track points, with dates in each record's own time zone.

What TripLibreLab needs from the data

NeedWhyWhere it comes from
Trip and stay start and end timesTo order the day and drive the timeline.trips.departure_ts / arrival_ts, visits.arrival_ts / departure_ts, with each row's tz
CoordinatesTo place stays and draw trips on the map.visits.lat / lon (the stay's centroid), else places.lat / lon
Links between trips and staysTo know where each trip started and ended.trips.origin_visit_id / destination_visit_id, else trips.origin_place_id / destination_place_id for hand-made or imported trips
Recorded route geometry (optional)To draw and replay the actual path.trips.route_polyline for the shape; raw_location_points inside the trip's time window for timed movement
Travel mode, purpose, place names (optional)Labels on the timeline and map.mode_user, else mode_auto; trip_segments for multimodal trips; places.name / category

Everything else in the file, including notes, addresses and the correction log, is left unread. The data contract lists those fields.

Which days are listed

A diary day is a local calendar date, in the time zone the records were made in, with at least one trip that departed on it. A trip that leaves at 23:40 and arrives at 00:15 belongs to the day it left. The day picker shows each day's trip count. A date that is missing means TripLibre recorded no trips that day, not that no travel happened; recording may have been off.

Missing and partial data

Real diaries have gaps. The behaviour, with the data it is based on:

  • A day with no trips is not offered in the day picker.
  • A trip with GPS points is replayed on its recorded timestamps, labelled measured.
  • A trip with a stored route but no points is drawn along its route with movement timed evenly between departure and arrival, and labelled as interpolated. TripLibre stores routes as shapes without timestamps.
  • A trip with no route is drawn between its start and end as a dashed schematic line, labelled as such.
  • A trip with a recording gap (TripLibre's has_gap) shows the straight connector across the gap dashed.
  • A stay that was still going on when you exported has no end time and is shown as ongoing.
  • A trip or stay without a location stays on the timeline but is left off the map, and the app does not crash.
  • An incomplete day is shown with what exists; nothing is filled in or guessed.
